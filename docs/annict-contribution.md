## 第1部: 方針（なぜやるか）

このサイトの配信データはAnnictのコミュニティ更新に依存しており、登録が追いついていない
作品がある。`scripts/audit-coverage.ts` はその抜け（TV放送データはあるが配信サービス0件の
作品）を注目度順に洗い出せるが、これまでは `content/works/extraServices.ts` で
**自サイトの中だけ**人力補完してきた。これは自サイトの表示は直るが、Annict本体のデータは
空のままなので、Annictを使う他のアプリ・他のユーザーには何も還元されない。

一方で `docs/growth-strategy-2026-08.md` は「作品ごとの配信データを機械可読で公開し、
出典表記を条件に他人の道具の供給元になる」ことを次の一手としているが、
**Annict由来のデータをサービス外へ再配布してよいかが利用規約から読み取れず保留中**。

この2つを1つの打ち手でつなぐ。**先に、こちらが一次情報で確認した配信情報をAnnictへ
登録して、コミュニティに実際に貢献する。その上で、再配布の可否をAnnictへ相談する。**

**この順序には意味がある。** 貢献の主目的は「サイトの配信網羅率が上がること」であり、
再配布の相談はその副次効果にすぎない。逆の順序（先に再配布の許可を求め、貢献は後回し）
にすると、Annictから見て「使わせてほしいから貢献する」という見返り目当てのやり取りに
見えてしまう。それだけでなく、実際にこちらが欲しいのは自サイトの配信網羅率そのものであり、
Annictへの登録は最初からそれ単体で価値がある行為である（再配布が実現してもしなくても、
自サイトの配信網羅率が上がるという成果は残る）。問い合わせのタイミングも、
「登録を何件かやってみてから」にする。

## 第2部: 貢献の手順（運用手順）

### 前提

- `node scripts/audit-coverage.ts [year] [season]` は `ANNICT_TOKEN`（Annictの個人用
  アクセストークン）を `.env.local` から読むため、**トークンを置いたローカルPCでしか
  動かない**（CI・サンドボックスでは動かない。CLAUDE.mdの環境変数節を参照）。
- 出力する (a) は「TV放送データはあるが配信サービス0件」の作品を注目度（watchers）順に
  並べたもの。これがAnnict側の登録待ちの疑いが強い候補になる。

### 手順

1. **候補を出す**
   ```
   node scripts/audit-coverage.ts [year] [season]
   ```
   (a) の一覧を上から見る。1回で全件を追わない。**注目度の高いものから少数ずつ**
   （目安: 1回のセッションで数件〜10件程度）に絞る。全件を追う保守コストは
   `content/works/extraServices.ts` と同じ理由（コメント参照）で避ける。

2. **一次情報で確認する**
   対象作品について、配信サービスの公式ページ・作品の公式サイト・公式Xアカウント等、
   **一次情報だけ**で「どの配信サービスで、いつから配信されているか」を確認する。
   まとめサイト・ニュースサイトの又聞き記事は不可。二次情報しか見つからない場合は
   その作品を見送る（推測で埋めない）。

3. **確認結果を手元に残す**
   出典URLと確認日を、`content/works/extraServices.ts` のコメントと同じ流儀で記録する
   （このファイル自体を直接編集するかは別途判断でよいが、少なくとも作業メモとして
   「作品ID・サービス名・出典URL・確認日」を残す）。Annict側の登録が反映された後に
   `content/works/extraServices.ts` から該当エントリを外せるか、次回の棚卸しで見直す
   （Annict本家にデータが載れば、こちらの人力補完は不要になる）。

4. **Annictへ手で登録する**
   確認した内容を、Annictのサイト上から**人が操作して**登録する（作品ページの
   編集機能・チャンネル紐付け等、Annict側のUIに従う）。

5. **一括投稿・自動投稿はしない**
   `scripts/audit-coverage.ts` はあくまで候補の洗い出し用であり、**この出力から
   Annictへ自動でデータを送るスクリプトは作らない・使わない**。コミュニティサービスへ
   スクリプトで機械的に書き込む行為は、負荷や荒らし行為とみなされうるため避ける。
   登録は毎回、人が1件ずつ確認しながら行う。

6. **繰り返す**
   新クールが始まるたびに (1) から繰り返す。`docs/operations.md` の定期点検サイクルに
   相乗りさせる運用が自然（本書はそこへの追記はしない。統合は別途行う）。
