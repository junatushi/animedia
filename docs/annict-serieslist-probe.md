# Annict の `seriesList` が使えるか確かめる手順（2026-08-11）

## 結論（2026-08-11・実測済み）

**Annict の `seriesList` は使えない。** `content/works/series.ts` の人力運用を続ける。
以下は結論の記録であり、**もう一度実行する必要はない**（Annict側が直ったかを確かめたく
なったときだけ再実行する）。

実測で分かったこと:

| 段階 | 結果 |
|---|---|
| `Work.seriesList` は存在するか | **存在する**（`SeriesConnection` → `Series`） |
| `Series` の形 | `annictId`・`id`・`name`・`nameEn`・`nameRo`・`works` |
| シリーズ名だけ取る | **取れる** |
| ＋シリーズ内の作品ID | **取れる**（ただし後述のとおり中身が別物） |
| ＋作品タイトルと放送クール | **HTTP 500**（Annictのエラーページが返る） |

そして致命的だったのは、**返ってくる作品IDが作品IDではなかった**こと。

| シリーズ | Annictが返したID | それが実際に指す作品（手元の8,957作品で照合） |
|---|---|---|
| 逃げ上手の若君 | 7729 | 羅小黒戦記 ぼくが選ぶ未来 |
| 逃げ上手の若君 | 7730 | シルバニアファミリー ミニストーリー ピオニー |
| 片田舎のおっさん、剣聖になる | 9557 | 異世界はスマートフォンとともに。2 |
| 片田舎のおっさん、剣聖になる | 9783 | きかんしゃトーマス 第13シーズン |
| 不死身な僕の日常 | 5371 | ブラッククローバー |
| 文豪ストレイドッグス | 4335 | 劇場版リトルウィッチアカデミア |

**どのシリーズも自分自身のIDを含んでいない**（逃げ上手の若君のシリーズに 10591 も 14132 も
無い）。`title` を要求すると500で落ちることと合わせて、Annict側のこのリゾルバが
壊れていると判断した。人力の対応表との一致は **6シリーズ中0**。

そのまま信じて実装していたら、逃げ上手の若君のページに
「シリーズの他の作品：羅小黒戦記、シルバニアファミリー」と表示していた。

この経験を受けて、スクリプトに**「作品は自分のシリーズに入っているか」の検査**を足した。
手元のデータと突き合わせないと気づけない、では検査になっていないため。

**PCでの作業です**（Annictへの通信とトークンが要るため、Claudeのセッションからは実行できません）。
所要時間は**5分ほど**。コマンドは1つだけです。

## なぜやるのか

いま `content/works/series.ts`（1期↔2期の対応表）は**人力**で維持しています。
GSCで需要が確認できた作品を1件ずつ、公式サイトで確認しながら足す運用です。

Annict には本来シリーズを表す `seriesList` というデータがあるはずで、それが使えるなら
**手作業が丸ごと不要になります**。ところがClaudeのセッション環境からはAnnictへ通信できず、
**応答を一度も見たことがありません**。

見たことのないフィールドを `lib/annict.ts` の一覧クエリに足すのは危険です。
名前や形が違うと**クエリ全体がエラーになり、サイト全部の配信情報が消えます**
（配信情報が主役のサイトなので、これは全面停止に相当します）。

そこで、**本番のクエリを触らずに、応答だけを見に行く**スクリプトを用意しました。

## このスクリプトが安全な理由

- **読み取りだけ**です。Annictには何も書き込みません
- **サイトの動作を変えません**。`lib/annict.ts` は一切触らず、このスクリプトは
  アプリのどこからも読み込まれていません。実行してもデプロイ済みのサイトに影響しません
- **フィールド名を決め打ちしません**。まずGraphQLに「Work型に `seriesList` はありますか」
  「それはどんな形ですか」と聞き、**返ってきた答えから問い合わせ文を組み立てます**。
  だから「無いフィールドを指定して失敗する」ことが起きません

## 出力の読み方

出力は5つの節に分かれています。**大事なのは⑤です。**

> 【2026-08-11の実測】この環境から実行したところ、Annictは `seriesList` を
> **持ってはいる**ものの、問い合わせると **HTTP 500** を返しました。
> そのため③で「どこまで取れるか」を浅い形から順に試し、**どこで落ちるか**を
> 突き止めるようにしてあります。③で止まった場合は⑤まで進みません（それが結論です）。

### ① Work型に seriesList があるか

```
✓  seriesList がある → SeriesConnection（OBJECT）
```

`✗ Work型に seriesList が無い` と出たら、そこで終わりです（自動化はできない＝人力を続ける）。
似た名前のフィールドがあれば一緒に表示されるので、それも貼ってください。

### ② 返ってくる形

シリーズの中身にどう辿り着くかを表示します。ここは技術的な情報なので、
読めなくて構いません。**そのまま貼ってもらえれば十分です。**

### ③ どこまで取れるか

浅い形から順に試して、どこまで応答が返るかを見ます。

```
✓  シリーズ名だけ: 取れた
✗  ＋シリーズ内の作品ID: HTTP 500 Internal Server Error
```

- **シリーズ名すら取れない** → `seriesList` は使えない。**そこで終わり**（人力運用を続ける）
- **名前は取れるが作品を列挙できない** → 「他の作品」を作れない。**そこで終わり**
- **作品IDまで取れた** → ④⑤へ進む

### ④ 実際の応答

作品ごとに、Annictが「同じシリーズ」と考えている作品が並びます。

```
14132 逃げ上手の若君 第二期
  シリーズ「逃げ上手の若君」: 2作品
    10591 逃げ上手の若君（2024-SUMMER）
    14132 逃げ上手の若君 第二期（2026-SUMMER）
```

### ⑤ 手作業の対応表との突き合わせ 【ここが判断材料】

いま人力で作った対応表と、Annictの答えが**一致するか**を出します。

```
✓  逃げ上手の若君: 一致（10591, 14132）
✗  クレバテス: 手作業=13593, 16555 / Annict=13593 / 取りこぼし: 16555
```

- **全部 ✓ なら** → Annictのデータが人力で確認した結果を再現できています。自動化を検討します
- **✗ が混じるなら** → Annictのシリーズ情報は不完全なので、**人力の対応表を続けます**。
  中途半端に自動化すると、繋がっていたリンクが消えたり、無関係な作品に繋がったりします

## 終わったら

**出力を最初から最後までそのまま貼って教えてください。**
⑤の結果を見て、次のどれにするかを決めます。

| ⑤の結果 | 次にすること |
|---|---|
| 全部一致 | `seriesList` を使う実装を検討する（ただし一覧クエリではなく、**作品個別の取得**か、スナップショット生成時に限定して入れる。一覧クエリを壊すリスクを避けるため） |
| 一部だけ一致 | 人力の対応表を主にしたまま、Annictを**候補の発見**にだけ使う（「このシリーズ、他にも作品がありますよ」と気づくための材料） |
| ほとんど一致しない／`seriesList` が無い | いまの人力運用を続ける。この手順書は結論の記録として残す |

失敗して赤い文字が出た場合も、**その文面をそのまま貼ってください**。
失敗しても本番のクエリには影響しません。

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `ANNICT_TOKEN が未設定です` | `.env.local` が無いか置き場所が違う。**リポジトリのフォルダ直下**に置く |
| `Unknown file extension ".ts"` | Node が古い。`node -v` で 22 以上か確認する |
| `失敗: … HTTP 401` | トークンが無効。https://annict.com/settings/tokens で発行し直す |
| `HTTP 500` が出る | 一時的な不調なら自動で3回まで再試行する。それでも出るならAnnict側で `seriesList` が壊れている＝③の結論として扱う（このスクリプトの想定内。エラーではない） |
| `MODULE_TYPELESS_PACKAGE_JSON` という警告 | **無視してよい**。毎回出る警告で、失敗ではない |
