## 2. 検証を通った施策（1件）

### ★ 窓の杜への自薦掲載

| | |
|---|---|
| 仕組み | 個人開発者が窓の杜編集部へ自ら売り込みメールを送り、記事として取り上げてもらう |
| 実測 | **ユーザー数6人**の個人開発サービスが自薦して掲載され、掲載日のアクセスが**平常時1〜3人/日から165人**に増加。窓の杜のXフォロワーは約8.9万 |
| 出典 | https://qiita.com/ogiharadevelopment/items/3986b11ea4522d7839f2 （2026-07-30。検証役が本文で数値の一致を確認） |
| コスト | メール文面の作成のみ（数十分）。無料・継続コストゼロ |
| リスク | 掲載されない可能性が高い（採否は編集部裁量）。規約リスクなし |
| 効果の性質 | **掲載当日のみのスパイク**。持続効果は薄い |

**採用理由**: 7領域で唯一、①出典が実在し ②数値が主張と一致し ③**当サイトと同じ「ユーザーが
ほぼいない個人開発」という規模**で成立した事例。他の候補はここで落ちている。

**注意**: N=1の報告であり、掲載は編集部の裁量。**「送れば載る」ではない。**
また単日スパイクなので、目標①（フォロワー100人）②（成果10件）への寄与は限定的。
売り込みの材料としては、公開API・埋め込みウィジェット・Discordコマンド・`.ics`購読が
既に揃っている（「作り込んだ個人開発」という説明が成り立つ）。

**実行はユーザー作業**（外部への送信のため）。文面は別途下書きできる。

## 4. 却下（理由つき）

| 施策 | 却下理由 |
|---|---|
| **Discord App Directory への掲載** | Discoverable になるには Verified 申請＋**100サーバー超のスケール承認**が必要（公式ポリシーで確認）。つまり掲載は流入経路ではなく、**先に100鯖を自力で稼いだ後の話**。到達手段が無い |
| **Chrome拡張の新規開発** | 個人開発者の実測（2年17本公開でユーザー数30台）が「ストア掲載だけでは伸びない」という否定材料。1人の開発余力を消費するだけ。出典: https://zenn.dev/ktg/articles/da898f8587df5d |
| **既存APIのMCP化＋レジストリ登録** | 調査が挙げた数値（Smithery月間43万開発者・mcp.so 2万server・5レジストリ合計10万超）が**挙げられた出典に存在しなかった**。確認できたのは「Smithery 6,000+サーバー」のみ。個別サーバーの流入実績は各社非公開で**構造的に測れない**。※アイデア自体が否定されたのではなく、判断材料がゼロという意味 |
| **Web Push通知** | 出典が月間30〜50億通を捌く企業のベンチマークで規模が別次元。加えて購読者の配信先を保存するDBが要り、**「DBなし」方針と衝突**する |
| **LINE公式アカウント** | 無料枠は月200通＝「配信回数×友だち数」。友だち100人なら**月2回**が上限で、友だちが増えるほど配信できなくなる。2026-07の「運用が重い」判断を数字が裏付けた |
| **Spotify Wrapped型の年間まとめ** | 出典（note記事）に主張の数値が**一切書かれていなかった**。加えて核心は「個人の視聴履歴」で、DBもログインも無い当サイトは持てない。集約版では「自分は特別」という共有動機が成立しない |
| **16Personalities型の規模参照** | 出典に診断回数の記載が無く、数値が未確認のまま |
| **海外・英語圏への展開** | 2026-07の「客層がズレる」判断を**再検証したうえで維持**。①在日外国人は日本国内サービスをそのまま使うので独自価値が薄い ②r/animeの自己宣伝規定は本文を確認できず ③LiveChart.me（月間数百万訪問・直接流入66%）は長年のブックマーク蓄積で転用可能な仕組みを含まない ④日本語のまま海外流入した場合の離脱率は実測データが1件も無い。英語版の翻訳保守は「1人＋自動化」と衝突 |
| **オフライン／コミュニティ接点** | 日英12回検索して**数値付きの実例がゼロ件**。同人イベント配布物・QRコード・大学のアニメ研究会・Discordでの自作ツール紹介、いずれも流入を示す報告が見つからなかった。判断材料が無いので着手しない |

### ニュースレター（Substack型）について

数値自体は正確だった（Substack平均開封率45%・一般メール21%）。しかし**開封率は既に購読者がいる
場合の指標**で、当サイトのボトルネックは「誰も登録していない」ことのほう。既存の `/api/notify` の
体裁を変えても新規流入にはならない。**購読者の獲得手段が示されるまで着手しない。**

## 5. 調査そのものから得た教訓

**7領域18件の候補のうち、4件で「出典が主張を支えていない」ことが検証で判明した**
（MCPの利用者数、Spotify Wrappedのシェア数、16Personalitiesの診断回数、診断コンテンツの出典URL）。
いずれも**もっともらしい数字が、実在するURLに紐付いた形で出てきた**ため、
検証工程が無ければそのまま採用していた。

診断コンテンツの例は特に示唆的で、数値（診断12,300回・シェア5,600回・完了率90%超）は
**PR TIMES発の実在情報**だったが、①出典URLが別サイトを指しており ②実際のキャンペーンは
**最大1万円分のAmazonギフト券抽選付き**という、無誘因では再現しない条件が落ちていた。

**教訓**: 外部調査の結果は、出典URLを開いて主張が書かれているかを確かめるまで採用しない。
これは `CLAUDE.md` の「一次情報で確認できた事実だけ」を、外部調査にも適用するということ。

## 6. 一次データが指している本命

外部チャネルが空振りだったことより重要なのは、**手元の実測が既に答えを持っていた**こと。

### 声優ページの面は、勝っているのに自分で絞っている

- 実測: **5.8位・CTR 9.5%**（作品ページは22.3位・1.3%）。4ページで全クリックの37.5%
- 現在 `/person/[name]/[year]/[season]` は **4,483ページ**が sitemap に載っている
  （`content/archive/people.json` から算出）。**2026-08-07に開いたばかりで、まだ索引が回っていない**
- ただし収録基準が「**そのクールに2作品以上出演**」（`lib/personPage.ts` の
  `PERSON_PAGE_MIN_APPEARANCES = 2`）で、**1作品だけの組が8,907件（全体の67%）捨てられている**
- さらに `CASTS_LIST` が長らく5だった影響で、**既存スナップショットは声優を取りこぼしたまま**
  （2026-08-11に40へ修正済みだが、過去クール分は再生成待ち。`docs/snapshot-regenerate.md`）

つまりこの面は、**①開いた直後で伸びしろが未測定 ②基準で3分の2を捨てている
③元データが取りこぼしている**、という三重に絞られた状態にある。

### なぜこれが「SEOで順位を上げる作業」とは違うか

これは「20.6位を18位にする」話ではない。**既に1桁順位を取れている面が1つあり、
そこだけがまだ開ききっていない**という話で、やることは順位改善ではなく**面の選択**にあたる。
7月に作った `/season` `/exclusive` `/rankings` が1ヶ月で表示ゼロなのと対照的に、
声優ページは4ページで6クリックを返している。

### ただし、これは仮説であって確定ではない

- 4ページ・63表示は**標本として小さい**。悠木碧・上坂すみれという知名度の高い2名に
  引っ張られている可能性がある
- 4,483ページが索引されたときに同じ順位を保つ保証は無い（薄いページの大量生成は
  逆に評価を落としうる。2026-07-13に閾値2を入れたのはまさにその懸念からだった）
- **判断材料は次回のGSC実測**。`content/analytics/gsc/` に毎日溜まるので、
  8月下旬に `/person/**` の表示回数とページ数の推移を見れば答えが出る

### 【2026-08-11 追記】季節性の切り分けを測れるようにした
