# 集客戦略リサーチ（2026-08-07）— 約100件の類似サービス調査からの結論

既存施策（SEO/GEOページ群・SNS自動投稿・埋め込みウィジェット・公開API）**以外**で
効く手を探すため、世界の類似サービス約100件を5領域に分けて調査した。
**出典URL付きの生データは `docs/research-2026-08/research-A〜E.md` に全文を保存してある**
（サンドボックスは破棄されるため、根拠を追えるようリポジトリに入れた）。
本書はそこから抽出した**判断と着手順**だけを残す。

調査領域: A=海外アニメDB/スケジュール20件、B=横断VOD「どこで見れる」20件、
C=日本のアニメ情報・番組表20件、D=会話なしで届く配信チャネル7カテゴリ、
E=アニメ以外も含む個人開発の配布手法22件。

---

## 0. 結論（3行）

1. **100件のうち長生きしている側は、例外なくSEOで勝っていない。**
   「他人のツールが依存するデータ供給元」になった結果として被リンクと定着を得ている。
2. 本サイトはその装置（公開API・ウィジェット）を**既に作ってあるが、
   ①存在が知られておらず ②使われても出典リンクが返ってこない設計**になっている。
   この2点は既存資産のままコード修正だけで直せる。
3. 本サイトにしか無い資産は一覧そのものではなく、
   **「Annictの生チャンネル名 → 国内配信サービス」への正規化**である。
   これは競合が構造的に真似しない位置にある（後述4章）。

## 1. 100件から出た唯一の共通構造

領域A〜Eで独立に調べたにもかかわらず、生存者の共通点が同じところに収束した。

| サービス | 継続年数 | 勝ち筋 |
|---|---|---|
| しょぼいカレンダー | 20年前後 | 全データAPI公開 → Ruby gem・Slack連携・録画システム(foltia)・視聴管理(Animetick)が生まれる |
| Annict | 12年 | **あえて公式アプリを作らず**「Annict Userland」で第三者アプリを掲載 |
| Trakt.tv | 16年 | オープンAPI。Plex/Kodi/Jellyfin向けscrobblerがOSSで多数生まれ、それが成長を牽引 |
| AniList | — | 無料GraphQL API → コミュニティ製Discord botが多数 |
| AnimeSchedule | — | 公開API v3 → Discord bot「ZeroTsu」が**5,679サーバー**に導入され間接露出 |
| AniDB | 24年 | ed2kハッシュによるファイル同定という実用ユーティリティが接着剤 |
| TMDB | — | "Powered by TMDB"のクレジット表記が**業界標準**になった |
| Jikan API | — | 「巨大サイトの非公式API」という位置そのものが恒常的な被参照を生む |

  つまり定着そのものが資産で、SEOは主要因ではない。

**含意**: 平均掲載順位19.8位を18位にする作業より、
「一度来た人が毎週戻る理由」と「他人の道具に組み込まれる理由」を作るほうが、
この分野の実績と整合する。

## 2. 既存資産の致命的な穴（すぐ直せる）

### 穴1: ライセンスに帰属義務が無い

`/developers`で公開API・ウィジェットを配っているが、
**「使うときは出典とリンクを出してください」と書いていない。**

駅データ.jpは利用規約で「駅データ.jpのデータを利用していること」と
「駅データ.jpのURL」の掲示を義務付けている。TMDBは"Powered by TMDB"表記を
業界標準にした。**これがあるかないかで、使われた回数がそのまま被リンクになるかが決まる。**

いま誰かが`/api/work/[id]`を使っても、こちらには何も返ってこない。
被リンクがゼロなのは告知不足だけでなく、**設計の問題**でもある。

### 穴2: ウィジェットを貼れる相手が構造的に限られている

引き継ぎメモが「ねじれ」と呼んでいた問題（`docs/handoff.md`）:
毎クール全作品レビューを書いていて配信先を書く動機が最も強いのは
VOD比較アフィサイトだが、彼らは**自分のアフィリエイト収益を他人に渡すことになるので
構造的に貼れない**。

**Reelgood が既にこの問題を解いていた。**
Publisher's Widgetは「**導入先メディア自身のアフィリエイトコードをそのまま使える**」
設計になっており、導入側の収益を奪わない。その結果、
New York Post傘下の Decider.com が採用している。

つまり「貼る側のIDを差し込めるようにする」だけで、
**競合だったVODアフィブログが配布先に変わる**。

> ### 🚫 却下（2026-08-07・ユーザー判断）
>
> **この案は採らない。** 理由は、実装すると `lib/embed.ts` の
> 「埋め込みHTMLに入るリンクは自サイト配下だけ」という`check.ts`の機械的検査を
> 外すことになるため。この検査は2026-07-28のバッジ誤リンク事故と同じ重大度で
> 運用してきた防壁で、**他人のサイトの中で表示される＝事故の影響が自サイトに閉じない**
> ものを守っている。得られるのは被リンクの見込み（VODアフィサイトが実際に貼るかは
> 未検証の推測）で、失うのは既にある防壁という交換になる。
>
> 穴2そのもの（配布先が構造的に限られる）は残るが、**別の解き方を探す**こと。
> この案の再提案は不要。

### 穴3: 定着装置（購読）が無い

領域A・D・Eが**独立に同じものを挙げた唯一の施策が `.ics`（カレンダー購読）**。
AnimeSchedule・Senpai.moe・しょぼいカレンダー・Annict・映画.comがいずれも
購読機能を持ち、日本のアニメファンにも定着済み。

購読された時点で「毎週能動的に見に来てもらう」必要が消える。
Direct流入49〜77%という生存者の数字は、この種の装置の帰結。
本サイトは放送スケジュールを既に持っているので、Route Handler 1本で出せる。

## 3. 手元データの実態（重要な訂正）

戦略を立てる前に `content/snapshots/` 64クール8,957作品を実測した。

**「16年分のデータがある」は誤り。**

| 年 | 配信情報がある作品 |
|---|---|
| 2010〜2013 | 各年 1〜2作品（実質ゼロ） |
| 2014〜2018 | 10〜18% |
| 2020〜2025 | 30〜46% |

2010年代前半のデータで「16年の推移」を語ると事実上のねつ造になる。

ただし**放送データがある作品に限れば2023〜2025年は86〜96%が配信情報つき**で、
2020年以降なら十分に語れる。低く見えた「44%」は、Annictの1クール分の
「作品」の約半分が番組データを持たない（OVA・劇場・短編・未登録）ことによる見かけ上の数字。

### 収録精度バイアスを除いた再計算（2026-08-07）

全作品で集計すると、Annict側の収録が年々良くなっている影響と実際の市場変化が
区別できない。そこで**各クールの注目度（watchers）上位30作品**だけで再計算した。
この層は**2021年以降どのクールでも99〜100%が配信情報つき**なので、
収録精度の向上では説明できない＝差分は実際の変化とみなせる。

| 年 | 上位30の配信率 | 平均配信社数 | ABEMA | Netflix | dアニメ | 1社独占 |
|---|---|---|---|---|---|---|
| 2019 | 53% | 2.2 | 34% | 41% | 58% | 47% |
| 2020 | 89% | 4.8 | 64% | 56% | 84% | 12% |
| 2021 | **99%** | 3.2 | 21% | 54% | 84% | 12% |
| 2022 | 99% | 4.1 | 44% | 53% | 85% | 15% |
| 2023 | 99% | 8.0 | 84% | 43% | 87% | 12% |
| 2024 | 100% | 8.7 | 95% | 57% | 97% | 3% |
| 2025 | 100% | 9.0 | 94% | 47% | 93% | 4% |

（2019〜2020は配信率が53%・89%と低いので、この2年は比較に使わない。**2021年以降が使える。**）

### 結論: 年次の推移はこのデータでは主張できない（2026-08-07・2段階の訂正）

上の表を見て最初は「マルチ配信化が起きている・ABEMAが台頭・独占が解消」と読んだが、
**これも誤りだった。** 上位30作品への絞り込みが補正するのは
**作品単位**の収録（その作品に配信情報が1件でもあるか）だけで、
**サービス単位**の収録（その作品の配信社が漏れなく記録されているか）は補正していない。

**決め手になった反例**: U-NEXTはスナップショット上2018年から存在するのに、
上位30作品での掲載率が **2021年=0% → 2022年=10% → 2023年=79%** と出る。
U-NEXTが2021年にアニメを配信していなかったはずはなく、これはAnnictの記録漏れ。

サービスが記録漏れしていると、作品は**実際より「独占」に見え、平均社数は少なく出る**。
つまり「独占12%→4%」「平均3.2→9.0社」「ABEMA 21%→94%」は、
**収録が良くなっただけでもまったく同じ形になる**ので、市場の変化と区別できない。

| 主張 | 判定 |
|---|---|
| Netflixが後退した | **取り下げ**（分母の変化。上位30では54%→47%でほぼ横ばい） |
| 独占が12%→4%に減った | **取り下げ**（サービスの記録漏れと区別できない） |
| 平均3.2→9.0社にマルチ配信化した | **取り下げ**（同上） |
| ABEMAが21%→94%に伸びた | **取り下げ**（同上） |

**使ってよいのは、記録が濃い直近年の「現状」だけ**（2025年は上位30×4クールで配信率100%）:

- 注目作は**1作品あたり平均9.0社**で配信されている
- **1社でしか見られない作品は4%**
- dアニメ93% / ABEMA94% / Prime96% / U-NEXT89% / Netflix47%

これは推移ではなく断面なので、収録漏れの向きの影響を受けない
（漏れがあるなら実際の社数はこれ以上ということしかない）。

**教訓（今後この種の数字を出すとき）**: 割合の変化を見るときは
①分母の変化と ②観測されるかどうかの変化 の両方を疑う。
①は上位N絞り込みで潰せるが、②は潰せない。**②が疑わしいなら推移を出さない。**
集計は `lib/streamingTrends.ts` に置き、`node scripts/streaming-trends.ts` で再生成する
（数字を文章に直書きしない）。`node scripts/check.ts` の
「配信集計の年次比較を禁じる」節が、年次差分を出す関数が生えていないことを検査する。

## 4. 競合が構造的に真似できないもの

一覧そのものには差別化余地が無い（dアニメが74〜82%をカバーするので
「どこで見られるか」の答えはほぼ全作品同じ、という引き継ぎメモの結論は正しい）。

**差別化があるのは正規化のほうだった。**
`lib/services.ts` の「Annictの生チャンネル名 → 国内配信サービス」への
名寄せ（表記ゆれ・TV局の除外・未知チャンネルの扱い）は、
本サイトが自前で書いた独自資産であり、Annictは持っていない。

誰がこれをやらないか:

| 相手 | 真似しない理由 |
|---|---|
| Annict | 視聴記録サービスであって、チャンネルは生データのまま持つのが正しい |
| JustWatch / Reelgood | 日本のローカルVOD（dアニメ等）の粒度が粗い。かつデータはB2Bで**売る**商材なので無料公開しない |
| VOD比較アフィサイト | データを開くと自分のクリック収益が消える。**構造的に不可能** |
| 各配信サービス公式 | 競合他社の配信状況を載せるわけがない |
| しょぼいカレンダー | TV放送の番組表であって配信サービスの名寄せではない |

つまり**「日本語アニメの配信サービス名寄せ表」を機械可読で無料公開する枠は、
現時点で空いている**。しょぼいカレンダーが20年かけて作った立ち位置と同じ型で、
かつ誰も座っていない椅子。

## 5. 施策（優先順）

### Tier 1 — 構造を変える

**① 公開データセット化＋帰属義務ライセンス**
`lib/services.ts` の名寄せ表をCSV/JSONで公開し、利用規約に
「出典表記＋`https://…`へのリンク」を明記（駅データ.jp型）。
既存の`/api/*`・ウィジェットにも同じ規約を適用する。
- 実装コスト: 小（生成スクリプト＋`/developers`の追記）
- **法務上の切り分け（重要）**: 名寄せ表そのものは本サイトの著作物なので
  **いま公開できる**。一方「作品ごとの配信実績」の再配布はAnnict由来のため、
  Annictの利用規約では「登録ユーザーが**本サービスを通じて**他の登録ユーザーに
  利用許諾する」と読め、サービス外への再配布可否が曖昧。
  **作品データの再配布は、Annictに確認が取れるまでやらない。**

~~**② ウィジェットに「貼る側のアフィリエイトID」欄を設ける**（Reelgood型）~~
→ **2026-08-07に却下**（2章・穴2の囲みを参照）。再提案しない。

**③ `.ics` カレンダー購読の追加**
3領域が独立に推した唯一の施策。Route Handler 1本。定着＝Direct流入の装置。
`?service=d_anime` 等で「自分が入っているサービスの分だけ」購読できると価値が跳ねる。

### Tier 2 — 到達（会話なし・制約に適合）

**④ Discord bot＋top.gg登録**
AnimeScheduleがZeroTsu（5,679サーバー）経由で得ている露出の型。
既存の`/api/work/[id]`をそのまま使える。サーバー管理者が「発見して追加」するので
リプライ営業に当たらない。課題はホスティング費用。

**⑤ Qiita/Zenn に「公開APIを出した」技術記事**
しょぼいカレンダー・Annictの被リンク経路そのもの。
ただしE領域の実測では Show HN が GitHub流入300倍・2日120スターだったのに対し
**Qiita/dev.toはほぼ効果なし**という報告がある。過度な期待はしない。

### Tier 3 — 収益（アフィリエイト10件の目標に直接効く）

**⑥ サービス別「独占配信作品」ページ**
dアニメが74〜82%をカバーする世界で、**利用者に新規加入の判断が発生する唯一の場面は
独占作品**。よって独占面はアフィリエイト転換率が構造的に最も高い。
既存の`/exclusive/[year]/[season]`は「クール軸」だが、
加入判断は「サービス軸」で起きる（「ABEMAに入るべきか」）。
`/service/[key]` に独占一覧を持たせるのが素直。データは既にある。

## 7. 目標との関係（正直な見通し）

追いかけている目標は**2026-11-06までに ①Xフォロワー100人 ②アフィリエイト報酬10件**。

### ①について: これまでの試算には見逃しがある（2026-08-07修正）

`docs/handoff.md` の試算は「会話をしない → フォロワーの供給源はサイト訪問者しかない
→ 100人には訪問者13倍が必要 → 不可能」という筋だった。**この前提が間違っている。**

**「リプライしない」と「到達しない」は同じではない。**
ユーザーが禁じたのは他人へのリプライ・DM・フォロー営業であって、
**他人が勝手に引用・リポストすること**は禁じていないし、そこに会話は要らない。
Xのフォロワーはサイト訪問者の転換ではなく、**Xの上での拡散**から来る。
試算はXをサイトの下流ファネルとして扱ったせいで、この経路を丸ごと落としていた。

**では、なぜ70投稿で拡散がゼロだったのか。** 投稿の中身が
「今日の放送」「注目作TOP5」＝**サイトを見れば分かること**しかないから。
これには2つの問題がある。

1. **フォローする理由が無い。** 同じ内容はブックマークすれば足りる。
2. **リポストする理由が無い。** 番組表を自分のフォロワーに見せる動機は誰にも無い。

つまりボトルネックは到達量ではなく**拡散に値する中身をまだ1度も出していない**こと。
そして本サイトは、3章で検証した**誰も数字で出していないデータ**を持っている。

**必要な数字が変わる。**

| | これまでの試算 | 拡散経路 |
|---|---|---|
| 前提 | 訪問者384人 × 転換率26% | 1投稿が1万人に表示 × フォロー率1% |
| 必要なもの | 訪問者を13倍にする | **刺さる投稿を1本当てる** |

これは「確実に届く」という意味ではない。**当たるかどうかは1本が跳ねるかに依存する**ので、
算術的に不可能だった前でとは違い**可能性はあるが予測はできない**、が正確な言い方になる。
ただし打席に立つ費用はほぼゼロで、外れても失うものが無い。

**具体的に出す素材**（3章のとおり**現状の断面のみ**。推移は使えない）:

- 2025年の注目作は**1作品あたり平均9.0社**で配信されている
- **1社でしか見られない作品は4%だけ**
- dアニメ93% / ABEMA94% / Prime96%

「配信がバラバラで何本も契約しないと見られない」という一般的な語られ方に対し、
**どれか1つ入っていれば大体見られる**というのが実際の数字。
通説の逆で、かつ他がデータで出していない。下書きは
`node scripts/streaming-trends.ts --post` が数字入りで生成する（手打ちしない）。

**やらないこと**: 数字を盛る・分母を伏せる・3章で取り下げた**推移**の主張を使う。
伸ばしたい数字のために正確性を落とすのは、このサイトが唯一持っている強みを削る行為になる。
なお2回続けて集計を読み違えた（Netflix後退 → 推移全般）ことを踏まえ、
外向けの数字は必ず `scripts/streaming-trends.ts` を通してから出すこと。

### 毎日の自動投稿の位置づけを下げる（2026-08-07決定）

上の分析の当然の帰結として、**Bluesky/Threads/Mastodonへの毎日の自動投稿を
「フォロワーを増やすための施策」として数えるのをやめる**。

理由は単純で、70投稿・フォロワー0という結果が既に出ているうえ、
中身が「今日の放送」「注目作TOP5」＝サイトを見れば分かることである限り、
**投稿の回数を増やしても頻度を変えても、フォローする理由もリポストする理由も生まれない**。
枠を増やす・時間帯を最適化する・文面を整える、といった改善は、
どれもこの構造に触れないので効かない。

ただし**止めはしない**。理由は次の3つで、いずれも「フォロワー獲得」とは別の話:

- アカウントが動いていること自体が、後から見た人への信用になる
- 投稿に含まれるリンクからの流入はゼロではなく、実測の材料になる
- 既に自動化されていて、動かし続ける限界費用がほぼゼロ

**したがって扱いはこうする:**

| | 方針 |
|---|---|
| 毎日の自動投稿（3媒体） | **維持のみ**。壊れたら直す。**改善に時間を使わない**（枠の追加・時間帯の調整・文面の作り込みは、効かないと分かっている場所への投資） |
| フォロワー獲得 | **単発の「そこにしかない数字」に集約**する（上の素材。`node scripts/streaming-trends.ts --post`） |

これは投げやりな判断ではなく、維持費が実際に発生しているからでもある
（Threadsの `Media Not Found` で2週間に4回の全滅、GitHub Actionsのscheduleの
間引きで約6日に1日は時間帯を丸ごと逃す）。**この維持費を払う価値はあるが、
その上に更に投資する価値は、いまのところ数字で支持されていない。**

なお**本書の他の施策（Direct流入と被リンクの複利）は3ヶ月では効かない**のは事実で、
そこは引き継ぎメモの判断どおり「どの数字がどこまで動いたか」で評価するのが妥当。
変わったのは「①に手が無い」という結論のほうだけ。
- **②は届きうる。** Tier 3⑥（独占×サービス軸）は
  「加入判断が発生する唯一の面」に直接置く施策なので、
  訪問者数が横ばいでも転換率側で動かせる。**3ヶ月で狙うならこちら。**

## 10. 第2ラウンドの調査（2026-08-07・領域F〜I）

埋め込みへのアフィID対応を却下したため、**穴2（配布先が構造的に限られる）の別解**と、
そもそも調査の幅を広げる目的で4領域を追加調査した。生データは
`docs/research-2026-08/research-F〜I.md`（出典URL付き）。

- **F: アフィリエイト成約の導線設計**（目標②に直結）
- **G: 「毎週戻る理由」を作る装置**（アニメ以外のニッチDBまで広げて棚卸し）
- **H: 会話なしでXのフォロワーを増やす実務**（目標①）
- **I: 隣接する未充足の検索需要**（誰も答えていない質問を探す）

### 分かったこと（重要な順）

**1. Xの「外部リンクは表示が抑えられる」は、いま成り立たない疑いが強い（H）**

これまでの週次キットは「全投稿に外部リンクが入っていることが表示を抑えている
可能性がある」を筆頭の仮説にし、**利用者に毎日2手増える実験**（本文からURLを外し、
URLは自分の投稿への返信に貼る）をやらせようとしていた。

再調査の結果、**2025年10月にリンクのデブーストが撤廃されたと複数媒体が報じており、
Xのプロダクト責任者も2026年に「リンクへのペナルティは1年以上前から無い」と発言**
している。日本語のSEO記事が今も「30〜50%減点」と書いているのは、撤廃前の情報が
複製され続けているとみられる。撤廃を裏付ける独立の実測は無いので断定はしないが、
**手数が増える実験を最優先で人にやらせる根拠としては弱い**。
週次キットの「4. 表示を増やす実験」を**手数の増えない順**に並べ替えた
（ハッシュタグを1個に → 単発の意外な数字 → 画像 → URLを返信に、の順）。

同じ調査で、2026年1月のアルゴリズム刷新でハッシュタグの加点はほぼ無くなったとされる
ことも分かった（減点される実測は無いが、付ける利益も薄い）。

**2. 「声優の出演作 × 配信先」は、需要があって誰も答えていない（I）**

知恵袋等で繰り返し聞かれているのに、答えているのは「同じ声優が演じたキャラ○選」型の
まとめ記事だけで、**出演作と配信先を一緒に答えているものが見当たらなかった**。
本サイトは `/person/[name]/[year]/[season]` を持っていたが、名前のとおり
**そのクールの出演作しか出せなかった**。スナップショットが `castNames` を持っていたので、
Annictへの追加取得ゼロで作品横断にできた（**実装済み**。詳細は `docs/operations.md` ⑱-6）。

**3. Annict の `Work.seriesList` を一度もクエリしていない（I・未検証）**

「見る順番」（シリーズの視聴順）は知恵袋で繰り返し聞かれる質問で、
有名フランチャイズは専業ブログやABEMAの特設ページで飽和しているが、
**中堅〜マイナー作品と今期の続編は空いている**。Annict GraphQL に
`Work.seriesList`（シリーズ名＋関連作品）が存在するのに `lib/annict.ts` は
一度もクエリしていない。

⚠️ **ただしサンドボックスからAnnictに到達できず、実際のレスポンスを見ていない**。
網羅率も、`summary` が構造化されているかも不明。**試験クエリで中身を確認するまで
実装しないこと**（推測でデータを埋めない方針に反する）。

**4. アフィリエイトのASP候補が具体化した（F）**

どのASPがどのサービスを扱っているかは管理画面でしか見えないが、
ASP解説記事から**始点になる候補**が拾えた（DMM TV=アクセストレード/afb、
U-NEXT=JANet/Link-A、Hulu=アクセストレード/バリューコマース）。
`docs/affiliate-setup.md` の「やること」に追記した。
**ASP登録の審査にPV数の下限を明記した一次規定は見つからなかった**ので、
月128人という規模を理由に申請を見送る根拠は無い。まず出す。

### 却下・見送り

| 施策 | 理由 |
|---|---|
| Strava/Untappd型のソーシャル機能（Kudos・バッジ・リーダーボード） | 月128人では「誰もいない掲示板」になる。教育分野では逆効果の研究報告もある（G） |
| 「配信終了予定」「見放題いつまで」への回答 | Annictは配信終了を記録せず**原理的に答えられない**。公式表示すら覆る実例があり、誤情報リスクが方針と正面から衝突する（I） |
| 「原作の何巻から」 | Annictは話数↔巻数の対応を持たない。人力の対応表は継続コストが高い（I） |
| 「サブスク解約すべきか」系 | 完全に大手VOD比較アフィサイトの土俵。Annictのデータ範囲外（I） |
| ユーザー投稿に依存する機能（CGM） | 供給が続かないと先細りする（攻略Wikiの例。G） |

### 残っている候補（未着手・判断が要る）

2. **「今期、あなたの契約サービスで何本見られるか」診断**（G）。localStorageのみで
   サーバー負荷ゼロにできる。効果の一次データは無く、当たるかは不明
3. **配信サービスの追加履歴**（G）。programsの履歴から「いつ配信に加わったか」を出す。
   ただし③と同じで**Annictの記録漏れと区別できない**ので、出し方には注意が要る
4. Discord bot（Tier 2④のまま。ホスティング費用の判断待ち）
