# 引き継ぎメモ（2026-09-04・表示速度。「2秒以上」の本当の原因を本番実測で特定して直した）

## 依頼

利用者から「アニメ視聴ガイドの表示が2秒以上。**Vercelの無料枠内のまま**速くしてほしい」。
対象は**トップ／シーズン一覧**（他のページ種別は未検証）。追加条件が4つ:
①恒久的に無料枠を超えない ②2秒未満 ③既存システムに不具合を起こさない
④**クールが増えるたびに作品数が増えることを織り込む**。さらに「**メインはスマホユーザー**」。

## いちばん大事なこと（前回の見立ては外れていた）

利用者からPageSpeed InsightsのAPIキーをもらい、**本番を初めて実地で測れた**。結果、
㊴（09-03のPR）で削ったDOMノード・バイト数は体感の主因では**なかった**。

- LCPは**100%が element-render-delay**（TTFBは6〜16ms＝サーバーは速い）。
- LCP要素は`h1.brand`。つまり「一番上の見出しが出るまで」が遅い。
- 主コストは**スクリプト評価**。トップ **802ms** に対しシーズンページ 469ms。
  逆にHTMLのパースはトップ **8ms**・シーズンページ 50ms。
  **「HTMLを読む」より「JSで組み立て直す」ほうが桁違いに高い。**

原因は2つ。どちらも**画面を見ている限り絶対に気づけない**。

1. **トップページ "/" のサーバーHTMLが空だった。** `useSearchParams()`を呼ぶ
   `TopPageExplorer`があったため、Next.js 14がSuspense境界を丸ごとクライアント描画へ
   退避させ、本番HTMLは`<div class="wrap"></div>`だけ（h1が0個・作品リンク0件）。
   2026-08-05に`/season/**`は直したのに、**トップだけ「ディープリンクに必要」として
   残していた**。サイトの正面玄関＝canonicalの指す先が1ヶ月間、空だった。
2. **CSSが外部ファイルだった。** `<link rel="stylesheet">`のせいでHTMLが届いた後に
   もう1往復。ローカル実測で約**370ms**（PSIの見積もりは150ms）。

## やったこと（PR: `claude/anime-guide-performance-n0vvh2`・コミット3件）

詳細と数字は`docs/operations.md`の㊴（09-03分）と㊵（09-04分）。

1. **トップのサーバー描画を復旧**。`useSearchParams`を捨て、`TopPageExplorer`が
   **hydrationより前に**`window.location.search`から1度だけクエリを読む。
   `SeasonExplorer`は**初期描画では使わず**マウント後の`useEffect`で反映する
   （初期描画で使うとサーバーHTMLと食い違い、クエリ付きで開いた人にだけhydrationが壊れる）。
2. **CSSをHTMLに焼き込んだ**。`scripts/build-inline-css.js`が`app/globals.css`を
   `app/inlineCss.ts`へ変換し、`predev`/`prebuild`で自動再生成。ミニファイアは
   「壊れると全ページ無スタイル」なので賢い最適化をしない（コメント除去と空白畳みだけ）。
3. **サムネイルをWebPに**（110枚・4.11MB→2.51MB＝**−39%**、見た目は同じ）。
   `sharp`は依存に入れない（再生成時だけ`npm install --no-save sharp`）。
4. **逆戻り防止の検査を3節追加**（`scripts/check.ts`）＋`verify-production.sh`に
   **A0節**（トップのh1・作品リンク・`rel="stylesheet"`が無いこと・`<style>`があること）。
   6通りの壊し方で落ちることを確認済み。

## 効果（ローカル本番ビルド・5回の中央値・CPU4倍/1.6Mbps/390×844のスマホ相当）

| ページ | 変更前 LCP | 変更後 LCP |
|---|---|---|
| `/season/2025/summer`（173作品） | 992ms | **472ms（−52%）** |
| `/season/2010/spring`（93作品） | 824ms | **400ms（−51%）** |
| `/anime/14876` | － | 320ms |

トップは変更前の数字が取れない（**HTMLが空でLCP要素が存在しなかった**）。
h1は0個→1個、作品リンクは0件→今期の全作品に復帰した。

## ④「作品数が増える」への答え（推測ではなく実測）

- 作品1件あたり **1.0ms・約4.6KB**（93作品400ms／173作品472ms から導出）。
- 500作品でも**約810ms**の見込み＝2秒には当たらない。
- それでも気づけるように、`verify-production.sh`に**シーズンページHTML 2MB
  （約430作品）で落ちる**しきい値を入れた。

## 無料枠への影響

- **ISR Writesは1件も増えない**（`revalidate`もページ数も変えていない）。
- トップのSSRが復活したぶんのCPUは**月あたり約22秒＝4時間枠の0.15%**。
- 転送量はHTML +8KB／回だが、**CSSのリクエストが1本減り、画像は39%小さくなる**。

## 残っていること

- **本番での答え合わせ（PSI）が未実施。** この環境から本番URLへ出られないため、
  **マージ後に本番を測る**方針で利用者と合意済み（2026-09-04）。
  測る対象はトップ／`/season/2025/summer`／作品ページの3面と、CrUXの実ユーザー値。
- ㉝のチェックポイント（2026-09-18）で無料枠3指標の実測を確認する。

## 見送った案（理由つき。再提案の前に読むこと）

- **flightペイロードの圧縮**（services/castNames）… バッジ・アフィリエイトの経路
  （重大度高）を触るのに、HTML全体の7.5%しか減らない。
- **折りたたみパネルの遅延描画** … パネルはDOMの1.4%しかない。
- **`legacy-javascript`のbrowserslist絞り込み** … 12KiBのために対応ブラウザを狭める。
- **カード一覧のイベント委譲化** … 効果は最大だが「不具合を起こさない」条件下で
  最も壊すリスクが高い。
