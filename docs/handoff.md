## 2026-08-05に打った手（次回の実測はこの前後で比較する）

いずれも**効果は未検証**。次回の実測が答え合わせになる。

1. **SSRが空だった問題の修正**（上記・最重要）。`components/TopPageExplorer.tsx`を新設し、
   `useSearchParams()`の呼び出しをトップページ専用に隔離した。
2. **過去クールを検索エンジンに開放**。sitemapが今期しか載せておらず、年・季節の切替も
   `<button>`で`<a href>`が無かったため、64クール・8,957作品ページが完全に不可視だった。
   sitemapに過去クール（シーズン64件＋配信1件以上の作品1,961件）を追加し、シーズンページに
   クロール可能な他クールへのリンク列を置いた。sitemapのURL数 約300 → 2,028。
   詳細は`docs/operations.md`の⑦-11。
3. **作品ページに「関連作品」を追加**。`/anime/{id}`は他の作品ページへのリンクを1本も持たない
   リンクの葉だった。同じクールの作品を、共演声優の重なり→注目度の順で8件出す。
   声優リンク判定で既に取得しているシーズンデータを使い回すので追加フェッチは無い。
4. **titleを幅の予算内に収めた**。日本語の検索結果は全角30〜33文字で切れるのに、実データ335作品で
   中央値47文字・99%が30文字超で、2026-07-27に入れたサービス名がほぼ全作品で切り捨てられていた。
   `lib/workTitle.ts`で予算内に収め、ブランド名（`| アニメ視聴ガイド`＝全角11文字）も
   `title:{absolute}`で外した。
5. **シーズンページのh1をtitleと一致させた**。h1が全ページ「アニメ視聴ガイド」固定で、
   titleの「2026年夏アニメ 配信情報一覧」と食い違っていた（Googleがtitleを書き換える原因になる）。
6. **Organization JSON-LDに`logo`を追加**（`/apple-icon`＝180×180 PNG。200が返ることを実測確認）。
7. **Annict障害時の作品ページをnoindexに**。取得失敗時に「データを取得できませんでした」を
   HTTP 200で返しており、エラー画面が索引に載りうる状態だった。
8. **SNS投稿のリンク先をシーズンページに変更**。`/?year=&season=`を貼っていたが、トップの
   canonicalは"/"なので検索エンジンには重複URLとしか見えず、順位を取らせたいシーズンページに
   何も渡っていなかった。`/season/{year}/{season}`に変更。
9. **`daily-digest.yml`に`dry_run`を追加**。動作確認の手段が「手動実行＝本番アカウントへ実際に
   投稿」しか無く、2026-08-05に確認のための手動実行を2回行った結果、ほぼ同じ本文が
   Bluesky・Mastodon・Threadsそれぞれに2回ずつ投稿された。投稿せず本文だけ出せるようにした。

## SNS運用について（2026-08-05のレビュー結果）

投稿文そのものより**到達の無さ**がボトルネックという結論は変わっていない
（3週間・約70投稿でフォロワー計4人）。レビューで挙がった改善余地:

- Bluesky/Mastodon/Threadsが**完全に同一の本文**を使い回している（Threadsのタグ数調整のみ差分）。
- 曜日固定の番組表なので、**毎週ほぼ一字一句同じ投稿**がリピーターに届いている。
- 告知型100%で、リプライを誘発する要素（問いかけ）が無い。
- Mastodonの投稿先が汎用の`mastodon.social`で、アニメ層の厚いインスタンスではない。

ただし`docs/x-growth-playbook.md`が言うとおり、リーチ（会話への参加）とフォロー転換は
人力前提の部分で、そこが動いていないと投稿文をいくら直しても到達は増えない。
**週次X成長キットのIssueのチェックリストを実際にこなしたか**をまず確認するのが先。

## 踏んだ落とし穴（再発防止）

- **SSRページはHTMLを取って中身を数える**（⑦-10）。ブラウザの表示は当てにならない。
- **dev server起動中に`rm -rf .next && npm run build`すると`.next`キャッシュが破損する**。
  ビルド前に必ずサーバーを止める。
- **`gh` CLIはこの環境に入っていない**。GitHubのIssue・Actions実行履歴を見たいときは
  GitHub MCPツール、またはリポジトリが公開なので`https://api.github.com/repos/junatushi/animedia/...`
  をWebFetchで直接叩く。
- **サンドボックスによっては外向き通信が全面的に遮断される**（2026-08-05のセッションでは
  `animedia-khaki.vercel.app`・`public.api.bsky.app`・`mastodon.social`のすべてが
  プロキシで403。SNSの実投稿・フォロワー数は取得できなかった）。
  その場合でも**ローカルで本番ビルドを起動すればHTMLの検証はできる**（今回の発見はこれで得た）。
- **`node scripts/check.ts`から`.tsx`はimportできない**（NodeはJSXを解釈しない）。
  検査したいロジックは素の`.ts`に置く（`lib/workTitle.ts`がその例）。
- Annict GraphQLスキーマにレンタル/サブスク区別フィールドは無い（introspection確認済み）。
- サーバー/クライアントで年・シーズン解決ロジックがズレるとSSRの`initialData`と表示が
  食い違う。`lib/resolveSeasonParams.ts`に共通化済み、変更時は両方への影響に注意。
- `ServiceTag.key`は`string`型（`lib/types.ts`）。
