# SEOプレイブック（2026-08-07版）

このサイトのSEOについて「何を根拠に、何をやり、何をやらないと決めたか」をまとめる。
毎日の点検は `node scripts/seo-audit.ts`（自動起票は `.github/workflows/seo-daily.yml`）。
**数字が悪化したらまずここを読む。** 新しい施策を思いついたときも、まず「やらないと決めたこと」を確認する。

調査方法: 2026-08-07に、Web検索で110サイト以上の一次情報を4領域
（①titleとCTR ②テクニカル/構造化データ ③AI検索とE-E-A-T ④日本市場とVOD競合）
に分けて収集した。以下の数値はすべて出典付きの実測・公式見解で、推測は含めない。

---

## 0. このサイトの立ち位置（前提）

- 実測（2026-07時点）: **平均掲載順位19.8位・検索クリック7件/28日・被リンクほぼゼロ**。
- 手持ちの在庫: 過去クール64件・作品ページ1,961件（配信1件以上）・勢力図/独占ページ68件。
- **構造的な弱点は被リンク**。オンライン上の全ページの約95%は被リンクゼロで、
  被リンクの無いページは競合クエリで実質順位が付かない（rhize.media 2026）。
  Backlinkoの1,180万件分析でも、トップ結果は2〜10位より被リンク数が3.8倍多い。
- **一覧そのものに差別化の余地は無い**。2025年の各クールでdアニメ1社が74〜82%をカバーし、
  1社独占は13〜21作品しかない＝「どこで見られるか」の答えはほぼ全作品で同じ
  （2026-08-06のセッションで手元のスナップショットから確認済み）。
  だから勝ち筋は「一覧で殴り合う」ではなく「**独自データ**」と「**配って言及を取る**」。

## 1. title と CTR

### 根拠
- 日本語のtitleは **title要素とh1要素を全角29文字以内**に収めるのが安全ライン
  （Web担当者Forum 2025-10-24）。表示領域は約600pxで、PCで全角28〜32文字、
  スマホで全角26〜33文字。**切れるかどうかは文字数ではなくピクセル幅で決まる**（Technogram 2026）。
- 主要キーワードをタイトルの**最初15文字以内**に置くと書き換えリスクが下がる。
  「サイト名｜カテゴリ｜記事名」型のテンプレ量産は書き換えの原因（gmotech.jp）。
- Googleがtitleを書き換える主因: 極端に長い/短い、内容不一致、キーワード詰め込み、
  title要素の欠落。**titleとh1の内容一致**が防止策になる（suzukikenichi.com）。
- 検索順位別CTR（2025年集計）: 1位 39.8% / 2位 18.7% / 3位 10.2% / 10位 1.6%。
  上位3位で全クリックの約7割（in-site.jp 2025）。
- 元記事「SEOタイトルの付け方とクリック率を最大化するコツ」（Web担当者Forum 2026-08-04）:
  月間検索1万回のキーワードで1位表示時にCTRが1%→2%になれば流入は単純に2倍。

### やったこと
- `lib/workTitle.ts` の `TITLE_WIDTH_BUDGET` を **32 → 29** に引き下げ（2026-08-07）。
  実測で29文字超が **64.5% → 7.7%** に減った（残りは削れない長い作品名）。
- 作品名だけで予算を超える作品（実測4.7%）は、接尾辞を3段階で落とす:
  ①「〜はどこで配信？」→ ②「〜の配信」→ ③ 作品名のみ。
  作品名は主キーワードなので**削らない**が、飾りは予算を超えてまで付けない。
- 作品ページのtitleはブランド名を入れない（`title: { absolute }`）。
  「アニメ視聴ガイド」は全角9.5文字ぶん幅を食うのに、「{作品名} 配信」で探している人への
  関連性を持たない。その幅を実際に検索されている配信サービス名に使う。
- **作品ページ以外も同じ規則にした**（`fitPageTitle`。2026-08-07）。
  レイアウトの `template`（`%s | アニメ視聴ガイド`）が付く種別を実測したところ、
  ランキング（全角32）・サービス別の長い名前（34）・声優別の代表作あり（30.5）が
  予算超過していた。**しかもランキングは過去クール68ページを検索エンジンに出した直後**。
  「予算に収まるならブランド名を付ける、収まらないなら落とす」という規則を1箇所に集約し、
  データが増えて名前が長くなっても自動で追随するようにした。
  結果: シーズン・独占配信はブランド名あり、ランキング・サービス別・声優別はなし。

### 未実施（保留の理由つき）
- **作品ページの h1 を title と一致させる**（現状 h1=作品名 / title=「作品名はどこで配信？…」）。
  書き換え防止策として挙がっているが、①titleは作品名から始まるので既に前方一致している
  ②ページ本文には `<h2>`「『X』はどこで配信されている？」があり内容は一致している
  ③全2,000ページの見出しを疑問文に変える見た目の変更を、根拠が「一致が望ましい」止まりの
  段階で入れるのは重い。**GSCで実際にtitleが書き換えられている証拠が出てから**着手する。

## 2. AI検索での可視性（GEO / AEO）

2026年時点で最も投資対効果が変わった領域。**Googleの順位とAI引用は別物**として扱う。

### 根拠
- AI Overviews表示時、トップ結果のCTRは約58%低下（Ahrefs 300,000キーワード、2025-12）。
  情報系クエリでは2024年半ば比61%減（Search Engine Land 2026）。
- **AIOの引用元のうち、同じクエリのGoogleトップ10に入っているページは38%のみ**
  （従来76%から急減。Ahrefs 863,000キーワード分析）。
  ChatGPTの最頻引用ページの28%はGoogleでの有機露出ゼロ。
  → **順位改善だけをGEO戦略にしてはいけない。**
- ページの「形」が引用率を大きく左右する:
  - **表形式のデータは抽出率 81% 対 平文23%**（mersel.ai 2026）
  - 比較表は引用率 +112%、FAQ形式 +89%（schema併用で最大+221%）、
    箇条書き +52〜67%、データ可視化 +103%（presenceai.app 2026）
  - Q&A形式は同一トピックの文章より **AI可視性 +45%**、
    **質問10件以上のFAQは引用可能性 +156%**（serps.io 2026）
  - **統計データの追加でAI可視性が最大40%、出典の追加で最大41%向上**
    （Princeton発のGEO研究 Aggarwal et al., KDD 2024）
- 鮮度: AI引用コンテンツの約半数は公開13週間以内。30日以内のページは古いページの3.2倍
  引用される（apiserpent.com 2026）。重み順は `dateModified` ＞ 画面上の更新日 ＞ 公開日。
- **LLMはJSON-LDを意味構造として解釈していない**（2026-02の統制実験。捏造したダミー
  schemaからもデータを抽出した／ziptie.dev 2026）。**可視HTMLが一次手段、schemaは副。**
- **llms.txt はAI引用と統計的に有意な相関が無く**、主要AI企業も本番読込を公式に
  コミットしていない（organikpi.com / livegodigital.com 2026）。
- 2026年の主流は「学習用ボットは選択的に、**検索/取得用ボット（ChatGPT-User・
  PerplexityBot 等）は許可**」（anagram.ai 2026）。

### やったこと
- **作品ページに配信サービスの表を追加**（`lib/workFaq.ts` の `buildServiceRows`）。
  バッジは機械から見ると「リンクの並び」でしかなく、見放題/レンタルの別もデータの出所も
  読み取れない。同じ情報を表として置いた。**表にリンクは入れない**（下の「やってはいけない」参照）。
- **実データ由来のQ&Aを全作品ページに展開**（`lib/workFaq.ts` の `buildDataFaq`）。
  配信サービス数・独占かどうか・放送開始日・曜日時刻・声優・制作の6観点。
  これまでは人力で書いた1作品にしかQ&Aが無かった。
  **データが無い質問は作らない**（「不明です」で水増ししない。Googleは文字数ではなく
  情報利得を測定している）。
- **配信サービス別ページに数字入りの要約文を追加**（`lib/seasonSummary.ts` の
  `buildServiceSummaryText`）。それまで本文は「〜で配信されている作品を人気順で
  まとめています」という、どのサービス・どのクールでも同じ定型文1つだけで、
  サービス数×クール数ぶんのページがタイトル以外ほぼ同一だった。
  「2024年夏アニメ全158作品のうち、dアニメストアでの見放題配信データがあるのは58作品。
  カバー率84%で12社中1位」のように出す。ハブページは説明文があってこそ効く。
- **シーズンページに数字入りの要約文を追加**（`lib/seasonSummary.ts`）。
  それまで h1 のあとがいきなり絞り込みUIと作品リストで、**文章が1文も無かった**
  （64クールぶんのページが機械から見て区別しにくい状態）。
  「2024年夏アニメは全158作品。見放題データがあるのは69作品で、1位がdアニメストア
  （58作品・84%）…」のように、他所が持っていない数字を置いた。
- robots.txt でのAIクローラ明示許可は**既に実施済み**（`app/robots.ts`）。

### やらないと決めたこと
- **llms.txt への追加投資**（既にある `app/llms.txt/route.ts` は残すが、育てない）。
  相関が確認できていないものに工数を割かない。
- **FAQPage 構造化データの獲得目的での増量**。FAQリッチリザルトは **2026-05-07 に表示終了**
  （Search Engine Journal 2026。2023-08の政府/健康サイト限定化に続く措置）。
  既存マークアップは残す（無害）が、**可視テキストのQ&Aにだけ投資する**。
- **WatchAction / BroadcastEvent の追いかけ**。Googleが対応するのは動画コンテンツ自体の
  放送状況で、「作品×複数配信サービス」の一覧に対応する専用schema.orgタイプは存在しない。

## 3. テクニカル

### 根拠
- **sitemapの `lastmod` は「一貫して正確」なときだけ使われる**。Gary Illyes は
  「lastmodが不正確なサイトはlastmodを付けない方がまし」と発言（2026-07-16）。
  Googleはlastmodを**信じるか丸ごと無視するかの二択**。
- 2026-06時点で実際に機能しているリッチリザルトは Breadcrumbs / Product /
  Merchant listings / Review / Video / AMP の6種（MBAdv 2026）。
  **TVSeries には専用リッチリザルト機能が無い**（Movieはムービーカルーセルとして機能）。
  `WebSite` の SearchAction（sitelinks searchbox）は2024-11に機能廃止。
- Core Web Vitals: LCP 2.5秒未満 / INP 200ms未満 / CLS 0.1未満、75パーセンタイルで判定。
  **サイトの43%がINP未達**で最頻の不合格指標。ランキングシグナル全体の約10〜15%相当で、
  コンテンツ品質が拮抗したときのタイブレーカー。
- **ファーストビュー画像（LCP候補）の lazy load は500ms超の遅延要因**（Martin Splitt）。
- クロールバジェットは Mueller/Illyes とも「数千URL未満なら気にしなくてよい」。
  → このサイト（約2,100URL）では**最適化に工数を割かない**。
- 単一言語・単一地域サイトに hreflang は不要（Mueller）。
- rel="next"/"prev" は2019年に完全非推奨。**新規に実装しない。**
- ヘルプフルコンテンツ系は**サイト単位のシグナル**で、低品質ページ比率が高いと
  高品質ページの評価も下がりうる（Plerdy / Lumar 2025）。
  Ahrefsの140億ページ分析では、インデックス済みページの96.55%が有機流入ゼロ。

### やったこと
- **sitemapの嘘の `lastmod` を止めた**（2026-08-07）。それまで内容が何ヶ月も動いていない
  `/about`・`/privacy`・`/developers` や、今期の全作品ページ（約250件）にまで
  毎日「今日更新」を申告していた。**今期の集計ページ（トップ・シーズン・独占・ランキング）
  だけに残し、他からは外した**。嘘のlastmodは、本当に毎日変わるページの鮮度シグナルまで
  道連れにする。
- **過去クールの勢力図・独占ページ68件をsitemapに載せた**。実装は年季を問わず動き、
  スナップショット由来で0.03秒級で開くのに、今期ぶんしか載せていなかった。
  ただし**配信データが20作品未満のクールは載せない**（「3作品の勢力図」は集計として
  意味を成さず、薄いページを大量に送るとサイト全体の評価を下げうる）。
- **構造化データの `dateModified` も同じ規律に揃えた**（2026-08-07）。
  sitemapのlastmodを直したあと同じ問題が残っていないか探したところ、
  6箇所（シーズン・ランキング・独占・サービス別・声優別・作品）が
  **全ページで無条件に「今日」を入れていた**。過去クールのページは
  `content/snapshots/` の確定データ由来で中身が1文字も動かないので、これは事実ではない。
  スナップショットは生成日を持っていないため正確な日付を出す手段が無く、
  **正確に出せないなら申告しない**（`structuredDateModified` が `undefined` を返し、
  `JSON.stringify` がフィールドごと落とす）。
  AI検索では鮮度の重み順が「dateModified ＞ 画面上の更新日 ＞ 公開日」で最も重いので、
  ここを汚す損は大きい。
- **一覧の先頭4枚のサムネを `loading="eager"` ＋ `fetchPriority="high"` に**。
  全サムネが `loading="lazy"` で、ファーストビューの画像＝LCP候補まで遅延していた。
  併せて `width`/`height` を明示してCLSを防いだ。

### 未実施
- サムネのWebP/AVIF化（`scripts/gen-thumbnails.js`）。転送量削減の効果はあるが、
  生成・キャッシュ運用が二重化する。LCPの実測を見てから判断する。
- INPの実測（`components/SeasonExplorer.tsx` のイベントハンドラ）。まず測る。
- **配信データが1件も無いクール13件**のシーズンページの扱い。
  全作品が「配信情報なし」になるので noindex か統合が要るが、
  ページ自体は実在の作品リストではあるので、GSCの実測を見てから決める。

## 4. 日本市場・競合構造

### 根拠
- 「2026年夏アニメ一覧」の上位はVODコンパス・ファミ通・クランクイン・アニメイトタイムズ等、
  **ニュース系大手かVODアフィ運営会社**。アニメイトタイムズは月間2,818万PV・
  公式X 67万フォロワーで、拡散網は複製不可。
- Googleは**JustWatch等のデータパートナー経由で配信情報を検索結果内に直接表示する**。
  単発の「○○ 配信」はSERP機能に奪われる領域。
- 一方 JustWatch は**国内クール横断の「季節ページ」を持たない**＝新クールSEOは個人サイトの土俵。
- 「○○はどこで見れる」型で上位を取っている小規模専門ブログの共通構造は
  「配信サービス一覧 → あらすじ・放送情報 → キャスト → 無料視聴の可否」の順。
  **このサイトの作品ページは既にこの順**（2026-07-27に並べ替え済み）。
- 個人サイトの勝ち筋は月間検索1000未満の**ロングテールの積み上げ**。
- ハブ＆スポーク構造は**ハブページ自体に300〜500字程度の説明文がある**ことが効果の条件。
- 被リンク獲得の王道は「**自社で調査した一次情報（独自集計）の公開**」。
  埋め込みコード（ウィジェット）の配布も定番の手段。
- 新規ページは早くて数日・通常1週間前後でインデックス、順位の輪郭は公開後2〜4週間。
  → **新クールのページは放送開始の1〜2週間前に出す**とスパイクに間に合う。

### やったこと / 既にやっていること
- 配信先ウィジェット・公開API・`/developers`（2026-08-06導入）。被リンクを作る側に回る施策。
- シーズンページの要約文（上記2）は、そのままハブページの説明文の役割も果たす。

### やらないと決めたこと
- **「アニメ 見放題」「動画配信サービス おすすめ」等のビッグワード**を正面から狙わない。
  大手比較サイトがASP予算で占有しており、個人サイト単体記事では取れない。
- **被リンクの依頼をしない**（Googleのリンクスパム対策に触れる／`/developers`の記載と矛盾する）。
  「使えるものを作ったのでよかったらどうぞ」で止める。
- VOD比較アフィサイト（spocale.com・anime-vod.com等）へのウィジェット配布。
  **彼らは配布先ではなく競合**で、貼ると自分のアフィ収益を他人に渡すので構造的に貼れない。

## 5. 明確にやってはいけないこと（出典つき）

1. **配信サービスの表やバッジの中に、行き先の違うリンクを入れない。**
   2026-07-28に人力補完の出典を「✓」でバッジ内に置いて誤タップ事故を起こしている
   （CLAUDE.mdの基本ルール・重大度高）。表は事実の一覧に徹し、リンクを持たせない。
2. **釣りタイトル・煽り語・誇張表現。** 短期CTRは上がっても直帰率増加で最終成果が下がる
   （mar-tech.media）。
3. **キーワードの詰め込みでtitleを不自然に長くする。** Googleの書き換え要因
   （suzukikenichi.com）。
4. **非表示コンテンツ・無関係なコンテンツへの構造化データ付与。**
   「Spammy structured markup」の手動対策対象（Google Search Central）。
   **可視テキストに無いものを構造化データに入れない。**
5. **薄いページを「情報利得のない水増し」で長くしない。** Googleは文字数ではなく
   情報利得を測定している（nkyseo.com / digitalapplied.com 2026）。
6. **鮮度シグナルの偽装**（実際の更新を伴わない更新日の書き換え、嘘のlastmod）。
   このサイトの「取得日≠確認日」ルールとも矛盾する。
7. **robots.txt で `disallow` と `noindex` を併用しない。** クロールできないため
   Googleが `noindex` を読めず、URLがインデックスされ続ける（Search Engine Journal 2025）。
8. **PerplexityBot 等のAI検索・取得系ボットを一律ブロックしない**（anagram.ai 2026）。
9. **放送が終わった作品に「いま配信中」と書かない**（CLAUDE.mdの基本ルール・重大度高／
   `lib/workAvailability.ts`）。逆に「もう配信されていません」と書くのも未確認なので禁止。
10. **新規ドメインのSEO効果を数週間で判断して施策を性急に転換しない。**
    効果発現の目安は半年〜1年（Google公式も「4か月〜1年」と明言）。

## 6. 毎日やること

`.github/workflows/seo-daily.yml` が毎日 Issue を起票する。中身は:

- `node scripts/seo-audit.ts --markdown` の指標（title幅・Q&A数・在庫・要約の網羅率）
- 「今日の1手」（`scripts/seo-audit.ts` の `BACKLOG` から日替わりで1件）

**指標に「気になる点」が付いたら、それを最優先で潰す。** 付いていない日は「今日の1手」を消化する。
消化した項目は `BACKLOG` から消し、このファイルの「やったこと」に移す。

不変条件（壊れたら赤にすべきもの）は `node scripts/check.ts` の
「作品ページ title の幅」「実データ由来のQ&A・表・要約」「放送終了作品の表現」節が見ている。
**これらの検査を消さないこと。**
