# スナップショット再生成の手順（2026-09-19改訂）

過去クール（2010〜2025年）のデータをAnnictから取り直して、
`content/snapshots/` を作り直すための手順書です。

**PCでの作業です**（Annictへの通信とトークンが要るため、Claudeのセッションからは実行できません）。
所要時間は**30分〜1時間**、うち大半は待ち時間です。

> 【2026-09-19の改訂点】目的を書き直しました。初版（2026-08-11）は「声優を5人しか
> 取っていなかった不具合（⑳）を直す」ための手順書でしたが、**その問題は2026-09-07に
> 解消済み**です（`content/archive/people.json` は再生成後の実数で更新されています）。
> いまの目的は下のとおり**作品ページをビルド時に焼けるようにすること**で、
> 成功の判定条件も変わりました（切断率ではなく `castCreditsComplete`）。

---

## なぜやるのか

作品ページ（`/anime/[id]`）は、過去クールの放送終了済み作品であっても
**アクセスのたびにAnnictへ問い合わせて**います。内容は二度と変わらないのに、

- 外部APIの往復（Annictへの負荷と、こちらの待ち時間＝表示速度）
- Fluid Active CPU と Provisioned Memory（**無料枠で唯一の超過項目**だった指標）
- ISR Writes（デプロイのたびにキャッシュが消えるので、クロールのたびに書き直し）

が毎日発生します。`docs/operations.md` の㊺で12時間だけ観測したときも、
`/anime/[id]` はこのサイトで**いちばん書き込みの多いルート**でした。

これを恒久的にゼロにする仕組みは**2026-09-14にもう入っています**（㊻）。
`lib/getWorkData.ts` は、スナップショットに `castCredits`（声優×キャラ名）が
入っているクールについては**Annictに一切問い合わせずに**作品ページを描き、
`app/anime/[id]/page.tsx` の `generateStaticParams` がそれをビルド時に焼きます。

**ただし既存の64ファイルは旧形式で `castCredits` を持たないため、いまは1件も有効に
なっていません。** この作業はそのスイッチを入れるためのものです。

| この作業で変わること | いま | 後 |
|---|---|---|
| 過去クールの作品ページの描画元 | Annictへライブ取得 | リポジトリ内のJSON（ネットワークに出ない） |
| 同ページの事前生成 | 0件 | 配信1件以上の全件をビルド時に焼く |
| 同ページのキャラ名（役名） | 空欄 | 表示される |
| Annictが落ちているときの表示 | エラー画面＋noindex | 通常どおり表示 |

## 事前に用意するもの

### ① Node.js 22 以上

コマンドプロンプト（または PowerShell）で確認します。

```
node -v
```

**先頭の数字が 22 以上ならOK**です（`v22.x.x` でも `v24.x.x` でも構いません）。
`v20` や `v18` と出た場合は https://nodejs.org/ から入れ直してください
（このリポジトリのスクリプトは `.ts` ファイルを直接実行するため、Node 22 の機能が必要です）。

### ② ANNICT_TOKEN

リポジトリのフォルダ直下に `.env.local` というファイルが必要です。

**すでにあるか確認する**（中身は表示しません）：

```
if exist .env.local (echo ある) else (echo ない)
```

`ある` と出れば準備完了です。次の「無い場合」は読み飛ばして手順に進んでください。

> 【`dir .env.local` で確認した場合の読み方】
> `dir` は先頭に「ドライブ C のボリューム ラベルがありません。」という**定型の見出し**を
> 必ず出します。これは「Cドライブに名前が付いていない」という意味で、
> **ファイルの有無とは関係ありません**。「ありません」という言葉に惑わされないでください。
> 判断するのは次の行です。
>
> ```
> 2026/07/15  15:29               877 .env.local
>                1 個のファイル                 877 バイト
> ```
>
> この行が出ていれば**存在します**。本当に無いときは `ファイルが見つかりません` と出ます。

**無い場合**は次の手順で作ります。

1. https://annict.com/settings/tokens を開く
2. 「Read」権限でトークンを発行する
3. リポジトリのフォルダ直下に `.env.local` という名前のテキストファイルを作る
4. 中身を次の1行にする（`xxxxx` の部分を発行したトークンに置き換え）

```
ANNICT_TOKEN=xxxxx
```

> `.env.local` は `.gitignore` 済みなので、コミットされることはありません。

## 手順

以下、コマンドはすべて**リポジトリのフォルダの中**で実行します。
最初にそこへ移動してください（パスはご自身の環境のものに置き換え）。

```
cd C:\Users\user\animedia
```

### 手順1：最新のmainを取り込む【いちばん重要】

**この手順を飛ばすと、作業しても何も直りません。** `castCredits` を保存するコードは
2026-09-14以降のmainにしか無いので、古いコードで再生成しても旧形式のファイルが
できるだけです。

```
git switch main
git pull origin main
```

取り込めたことを確認します。

```
node scripts/check.ts
```

出力に `✗` の行が無ければOKです（`✓` と `ℹ` だけ）。

> 【もし `git pull` でエラーが出たら】
> 「Your local changes would be overwritten」と出る場合、手元に未保存の変更があります。
> `git stash` を実行してから `git pull origin main` をやり直してください。

> 【`cannot lock ref 'HEAD'` / `HEAD.lock: File exists` と出たら】
> gitが異常終了したときなどに残るロックファイルの残骸です。消せば直りますが、
> **動いているgitがある状態で消すとリポジトリが壊れる可能性がある**ので順番を守ること。
>
> 1. このフォルダを開いているアプリ（VS Code・GitHub Desktop・SourceTree等）を閉じる
> 2. gitが動いていないか確かめる。何も表示されなければOK
>
>    ```
>    tasklist | findstr /i git
>    ```
>
> 3. ロックファイルを消す
>
>    ```
>    del .git\HEAD.lock
>    ```
>
> 4. 他のロックも残っていないか確認する（`ファイルが見つかりません` ならきれい）
>
>    ```
>    dir .git\*.lock
>    ```
>
> 5. `git status` がエラー無く動くことを確かめてから、`git switch main` をやり直す
>
> ロックファイルを消してもコミットや作業内容は消えない（「操作中」の目印の空ファイル）。

### 手順2：スナップショットを再生成する（30分程度・待つだけ）

```
node scripts/snapshot-past-seasons.ts 2010 2025 --force
```

- `--force` は「既存ファイルを上書きする」指定です。**これが無いと全部スキップされます**
- 64クール（16年 × 4クール）を1つずつ取り直します
- Annictに負荷をかけないよう1クールごとに0.8秒待つので、時間がかかります
- **途中でウィンドウを閉じないでください**

進行中はこのように1行ずつ出ます。

```
✓ 2010-winter: 48 作品 → C:\Users\user\animedia\content\snapshots\2010-winter.json
✓ 2010-spring: 52 作品 → ...
（…64行…）

完了: 生成 64 / スキップ（既存）0 / 失敗 0
```

**「失敗 0」であることを確認してください。**

> 【`✗` が出た年があった場合】
> **そのままもう一度実行しても直りません。** 失敗した年は古いファイルが残っているため、
> `--force` を付けずに実行するとスキップされてしまいます。
> 失敗した年を指定して、`--force` 付きで取り直してください。
>
> ```
> node scripts/snapshot-past-seasons.ts 2017 2017 --force
> ```
>
> （`2017` の部分を、`✗` が出た年に置き換えます。複数年あれば1年ずつ繰り返します）

### 手順3：3つの索引を作り直す

スナップショットから作られている索引が、古いままだとズレます。3つとも実行します。
それぞれ数秒で終わります。

```
node scripts/build-archive-index.ts
node scripts/build-person-index.ts
node scripts/build-studio-index.ts
```

### 手順4：**スイッチが入ったことを確認する**【この作業の成否はここで決まる】

```
node scripts/check.ts
```

見るのは**この1行だけ**です。

```
ℹ  スナップショットの形式    → castCredits あり 64/64クール（作品ページを焼ける）
```

**64/64 になっていれば成功**です。`0/64` のままなら手順1（`git pull`）か
手順2（`--force`）のどちらかが効いていません。

あわせて、出力全体に `✗` の行が無いことを確認してください。

> 【なぜ「切断率」を見ないのか】初版はここで `ℹ スナップショットの切断率` を見て
> 「87.9%から下がっていれば成功」と判定していました。それは声優を5人しか取れて
> いなかった時代の判定で、**その問題は既に解消しています**（いま実行しても切断率は
> 最初から低い＝判定に使えません）。いま確認すべきは `castCredits` の有無です。

### 手順5：**成果物の大きさを確認する**【2026-09-19追加】

再生成すると、過去クールの作品ページが**ビルド時に焼かれるようになります**。
その分デプロイ成果物が大きくなり、Vercelの Deployment Storage（無料枠10GB）に効きます。
**先に確認してからpushしてください。**

```
npm run build
node scripts/check-build-size.js
```

最後に出る行を見ます。

```
合計 ○○MB / 予算 650.0MB（○○%）
結果: 全てOK
```

- **`結果: 全てOK` なら、そのまま手順6へ進んでください**（想定内です）
- `結果: NG` と出たら**pushせずに知らせてください**。予算の決め方と手当ては
  `scripts/check-build-size.js` の冒頭に書いてあります

同時に出る「成長の見通し」の行が、**このまま何年で予算に当たるか**を毎回計算します
（クールが増えれば成果物は自動で増えるため）。ここが2年を切ったら手当ての時期です。

### 手順6：保存して反映する

生成されたファイルをコミットして送ります。

```
git add content/
git commit -m "スナップショットを再生成（castCredits を保存し、作品ページを事前生成できるようにする）"
git push origin main
```

pushが通れば、数分でVercelに反映されます。

> 【`LF will be replaced by CRLF` という警告が大量に出るのは正常】
> Windowsのgitが持つ改行コードの自動変換（`core.autocrlf`）の通知で、**エラーではない**。
> スクリプトが書くJSONの改行はLF、Windowsで取り出すときはCRLFに変換されるが、
> **リポジトリに保存される中身はLFのまま**で、JSONの内容は変わらない。
> 64個のスナップショット全部について出るので大量に見えるだけ。そのまま進めてよい。

## 終わったら

次の2つをそのまま貼って教えてください。

1. `node scripts/check.ts` の **「スナップショットの形式」の行**
2. `node scripts/check-build-size.js` の **最後の3行**（合計・成長の見通し・結果）

数日後に、Vercelのダッシュボードで ISR Writes と Fluid Active CPU が
下がったかを一緒に確認します（**ビルド成果物の実測と、Vercel側の課金の実測は別物**です。
下がる「はず」で終わらせず、必ず実測で確かめます）。

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `ANNICT_TOKEN が未設定です` | `.env.local` が無いか、置き場所が違う。**リポジトリのフォルダ直下**に置く |
| `dir .env.local` が「ボリューム ラベルがありません」と出て無いように見える | それは `dir` の定型の見出しで、ファイルの有無とは無関係。`if exist .env.local (echo ある) else (echo ない)` で確かめる |
| `Unknown file extension ".ts"` | Node が古い。`node -v` で 22 以上か確認する |
| 何も起きずすぐ終わる（生成 0 / スキップ 64） | `--force` を付け忘れている |
| `対象は過去年のみです` と出る | 終了年に今年を指定している。**前年**までにする |
| 途中で `✗` が出た | 上の「`✗` が出た年があった場合」を参照。**年を指定して `--force` で取り直す** |
| 手順4が `0/64` のまま | 手順1の `git pull` が効いていない（古いコードで生成した）。手順1からやり直す |
| 手順5が `結果: NG` | **pushせずに知らせる**。予算を超えている |
| `git push` が拒否される | 先に `git pull origin main` を実行してから push し直す |
| `cannot lock ref 'HEAD'` / `HEAD.lock: File exists` | ロックファイルの残骸。手順1の注記を参照（**gitが動いていないことを確かめてから** `del .git\HEAD.lock`） |
| `MODULE_TYPELESS_PACKAGE_JSON` という警告が出る | **無視してよい**。毎回出る警告で、失敗ではない |
| `git add` で `LF will be replaced by CRLF` が大量に出る | **無視してよい**。Windowsの改行コード自動変換の通知で、保存される中身は変わらない |

## 次に同じ作業が必要になるとき

- **年が変わったとき**（例：2027年になったら）。ただしそのときは前年分だけでよく、
  `--force` も不要です。

  ```
  node scripts/snapshot-past-seasons.ts 2026 2026
  ```

  そのあと手順3〜6は同じように行います（**手順5の成果物の確認も毎回行う**こと。
  1クール増えるごとに作品ページが増えるため）。
- スナップショットに入れる項目を増やしたとき（今回のような全件再生成）。
