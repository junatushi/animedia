## 読み取り（事実と推測）

**事実**
1. **表示は出ている。** `docs/operations.md` の記録では、2026-08の通常投稿は1件あたり
   インプレッション2〜5（固定ポストでも36）だった。今回は133〜291で、桁が違う。
   シャドウバン解除（㉘）と、1日1投稿・本文URLなし・画像付きの形（`x-growth-playbook.md` の
   2026-08-16更新）の後の値である。
2. **反応と流入はほぼ無い。** 4件で いいね1・RT0・プロフィールアクセス1・詳細クリック2。
   エンゲージメント23の大半は、いいね・RT・返信・クリック以外の操作（画像の拡大など）と見られる
   （推測: 画面に内訳が無いので断定できない）。
3. 4件すべてに**返信が1件**ある。

**推測（未検証）**
- 返信1件は、運用方針で「URLはリプライで貼る」としている**自分の返信**だろう。そうなら外部からの
  反応はゼロで、リンクのクリックは**このスクリーンショットには出ない**（返信側のアナリティクスを
  見る必要がある）。
- 木曜の185より金曜の291が高いのは曜日の差か、フォロワーの閲覧時間か、画像の見え方かは切り分け不能
  （n=1、条件が同時に複数変わっている。10/14は文面が「【水曜】…今期アニメ6本」、10/15以降は
  「木曜放送・配信がある2026年秋アニメ16本」と**書式が変わっている**）。
- 本文は先頭3行で「…」に切られている。件数と先頭3作品しか見えないので、**先頭に何を置くか**が
  表示後の行動を左右する可能性がある。

## 診断

`docs/daily-ops.md` の分岐に当てると、**「インプレッションは出ているのにフォロワーが増えない」側**
に入った。8月までの「表示が出ない」問題は解けており、次の詰まりは**表示→プロフィール→サイト**の
転換である。文面を磨く前に、転換の経路（固定ポスト・プロフィール・リプのリンク）を見る。
ただし**母数が小さい**（インプレッション842・プロフィールアクセス1）。1件の差を根拠に
投稿の中身を変えない。

## いまの方針

1. **投稿の形は1週間変えない。** 1日1投稿・本文URLなし・季節タグ1個・画像付き、を維持する。
   伸びた原因を切り分けられなくなるので、頻度を増やす・URLを本文に戻す・タグを増やす提案はしない。
2. **転換の経路を先に点検する**（実行はXアカウント側の手動）。
   - 固定ポスト: 反応が最も良かった投稿（現時点では10/16金曜の291か、24時間後の10/17土曜）に差し替えを検討。
     ただし固定ポストに画像付きの一覧を置くなら、プロフィールを見た人がサイトへ行く導線（リプのURL）
     が見える形にする。
   - プロフィール: 「今期アニメがどこで配信されているか一覧でわかるサイト」と一目で分かる説明＋URL。
     現状の文面は画像から読めないので、次回プロフィール画面のスクリーンショットも渡してほしい。
3. **測り方を固定する。** 取得は**投稿の24時間後**（途中の値と完全な値を並べない。10/17は13時間後なので
   次回更新する）。毎回、**リプライ（URLを貼った自分の返信）のアナリティクスも撮る**。
   サイトへ来たかは `/admin/analytics` の `ref` で見る（Xからの流入は `?ref=` 付きかどうか要確認）。
4. **比べるのは同じ曜日どうしだけ。** 水曜は10/14と10/21、のように。曜日が違う行の優劣は言わない。
5. **1度に変える要素は1つ。** 次に試すなら先頭3行の見せ方（例: 独占配信や注目作を先頭に置く）を
   水曜だけ変え、翌週の水曜と比べる。実装が要る（`scripts/lib/build-digest.js`）ので、
   やる場合は別PRで計画を出してから。**今回は提案のみで実装していない。**
6. **見直しの条件（2週間分＝14件が溜まった時点）。**
   - プロフィールアクセスが1日1未満のまま → 転換の問題を確定扱いにして固定ポスト・プロフィールを直す。
   - インプレッションが100を下回る日が続く → 表示側の再点検（シャドウバン再発の確認を含む）。
   - どちらも満たさない → 現状維持。

## 次回の更新手順

1. 利用者が投稿の24時間後のスクリーンショット（本体＋リプライ側）を渡す。
2. 画像を `docs/x-analytics/<日付>/` に置き、上の表に1行足す（取得時点を必ず書く）。
3. 14件溜まるまでは方針を変えない。溜まったら「いまの方針」6項の条件で判定する。

## 実験: 本文URL1回（2026-10-21・10-28の水曜、airingのみ）

実装: `scripts/lib/build-digest.js` の `X_BODY_URL_EXPERIMENT_DATES`（日付配列）。その日のXの airing 下書きだけ
本文末尾にURLが入り、返信用URLの枠は出ない。他の曜日・種別・他の投稿先・週次キットは変わらない。
検査は `node scripts/check.ts` の「Xの投稿方針」(7)（日付が水曜か／対象外は従来どおりか／最終日から14日超で失敗）。

| 日 | 本文URL | インプレッション(24h後) | リンククリック | プロフィールアクセス | 備考 |
|---|---|---|---|---|---|
| 10/14(水) | なし | 133 | （項目なし） | 0 | 比較元（書式が違う点に注意） |
| 10/21(水) | あり | | | | |
| 10/28(水) | あり | | | | |

**中止条件**: 実験日のインプレッションが、同じ週のURLなし投稿の中央値の半分未満 → シャドウバンチェッカーを確認し、
`X_BODY_URL_EXPERIMENT_DATES` を空にして戻す（閾値は提案値で根拠は未検証）。
**終わったら**: 結果を上の表に書き、配列を空にする（空にしないまま14日過ぎると検査が落ちる）。
